# Приёмка: резервное копирование и восстановление БД (28.09.2026)

Пункт DoD `docs/tz.md` §11.1: «Бэкап БД создаётся и **успешно восстановлен** (проверка выполнена, а не
заявлена)».

## Как воспроизвести

```powershell
pwsh -File tools/db-backup.ps1                  # дамп в data/backups, ротация 14 дней (-KeepDays)
pwsh -File tools/db-restore.ps1 -Dump data/backups/geopuls-geopuls-<дата>.dump
```

## Что делают скрипты

- **`db-backup.ps1`**: `pg_dump -Fc` выполняется **внутри контейнера `db`**, файл копируется на хост
  через `docker compose cp` (перенаправление бинарного потока через PowerShell портит дамп),
  затем удаляются копии старше срока хранения.
- **`db-restore.ps1`**: копирует дамп в контейнер, пересоздаёт **отдельную** базу
  (`geopuls_restore_check`), восстанавливает `pg_restore --no-exit-on-error`, сравнивает число строк
  ключевых таблиц с рабочей базой и **падает с ненулевым кодом, если цифры разошлись**. Проверочная
  база удаляется автоматически (нужна — флаг `-KeepRestored`).

## Ограничения и что дальше

- Расписание бэкапов (cron/systemd-timer на VPS) и хранение вне машины — остаток Этапа 7: локально
  проверен сам механизм, а не эксплуатационный регламент.
- Восстановление **поверх рабочей** базы требует явного флага `-Force`: по умолчанию скрипт
  восстанавливает в отдельную базу, чтобы проверку нельзя было случайно превратить в потерю данных.
- Проверка восстановления — обязательный пункт перед релизом (раз в квартал по §9.1 ТЗ), сам скрипт
  для этого уже готов.
