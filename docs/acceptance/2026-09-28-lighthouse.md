# Приёмка: Lighthouse-прогон (28.09.2026)

Критерий §11.1: «Нагрузочный прогон и Lighthouse-прогон задокументированы».

## Как воспроизвести

```powershell
cd frontend
$env:CHROME_PATH = "$env:LOCALAPPDATA\ms-playwright\chromium-1243\chrome-win64\chrome.exe"
npx --yes lighthouse "http://localhost:3000/?city=tomsk&category=cafe" --quiet `
  --chrome-flags="--headless=new --no-sandbox" `
  --output=json --output-path="..\data\processed\lighthouse.json"
```

Проверяется **production-сборка в контейнере** (`web` из `docker compose`), а не dev-сервер: dev по
определению медленнее и не отражает то, что увидит пользователь.

## Результат

| Категория | Оценка |
|---|---:|
| Performance | 70–76 (три прогона) |
| **Accessibility** | **100** |
| **Best practices** | **100** |
| **SEO** | **100** |

Метрики (прогон после исправлений): FCP 0.8 с, LCP 2.7–3.9 с, TBT 710–810 мс, CLS 0.057, Speed Index 2.4–2.5 с.

Первый прогон дал Best practices 96: в консоли были две ошибки 404 — приложение запрашивало
`/favicon.ico`, которого не было. Добавлена иконка `frontend/app/icon.svg` (гексагон H3 в фирменных
цветах), после чего ошибок в консоли нет и Best practices = 100 (проверено: число ответов ≥ 400 в
прогоне — 0). Дополнительно добавлен `preconnect` к `tiles.openfreemap.org`.

## Что стоит улучшить (после MVP, не блокирует приёмку)

1. **TBT 0.7–0.8 с и «unused JavaScript»** — основная часть времени уходит на разбор и инициализацию
   MapLibre GL (≈ 700 КБ JS). Варианты: ленивая загрузка карты (`next/dynamic`), вынос карты в
   отдельный чанк, отказ от лишних слоёв стиля подложки.
2. **LCP 2.7–3.9 с** — зависит от загрузки стиля подложки и первого кадра карты; добавлен `preconnect`
   к `tiles.openfreemap.org`, дальше помогает self-hosted подложка (PMTiles, ADR 0002) — она убирает
   внешний хост из критического пути.
3. **CLS 0.057** — в норме (порог «хорошо» < 0.1), дополнительно улучшать не нужно.
4. Разброс Performance между прогонами объясняется программным рендерингом в headless-браузере без
   прогретого кэша: цифры стоит сравнивать в одинаковых условиях, а не между запусками.
