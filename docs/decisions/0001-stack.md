# ADR 0001. Стек и версии

Дата: 28.09.2026. Статус: принято.

## Контекст

MVP: тепловая карта плотности POI по H3-ячейкам для города (старт — Томск). Один разработчик,
один VPS, бюджет близок к нулю, данные — открытые. Требования: быстрая разработка, честная геометрия
(плотность вместо количества), дешёвая эксплуатация.

## Решение

| Слой | Выбор | Версия |
|---|---|---|
| Язык импортёра | Python | 3.14 (проверены колёса: `h3 4.5.0`, `shapely 2.1.2`, `pyproj 3.8.0`, `pyogrio 0.13.0`, `geopandas 1.1.4`, `numpy 2.5.3`, `pandas 3.0.6`) |
| Менеджер зависимостей Python | `uv` (pyproject + uv.lock) | uv 0.12.10 |
| БД | PostgreSQL + PostGIS | `postgis/postgis:17-3.5` |
| Сетка | H3 (Uber) | ядро 4.5.0, res 9 (детально) / 8 (обзор) |
| API | FastAPI + Uvicorn, SQLAlchemy 2.0 async + asyncpg, Alembic, Pydantic v2 | актуальные на дату старта |
| Фронтенд | Next.js + TypeScript, MapLibre GL JS, `h3-js` | Next 16.x, MapLibre 6.x, h3-js 4.5 |
| Пакетный менеджер JS | npm | 11.x (pnpm/yarn в окружении нет) |
| Инфра | Docker Compose, Caddy | Docker 29 |

## Рассмотренные альтернативы

| Альтернатива | Почему не выбрана |
|---|---|
| GeoDjango (Python + Django) | Больше «магии» и веса; для read-only API хватает FastAPI |
| Node/TypeScript на бэкенде | Гео-инструменты в Python зрелее (pyogrio, h3-py), а импорт PBF — основная работа |
| PostGIS + `pg_h3` (расчёт H3 в БД) | Требует кастомного образа БД; расчёт в Python при импорте проще и достаточно быстр для наших объёмов |
| Колоночное хранилище (DuckDB/Parquet) вместо PostGIS | Нет точного радиуса `ST_DWithin` и удобных транзакций; объёмы малы, преимущество не оправдано |
| Vite + React вместо Next.js | Проще для SPA-карты, но теряется задел под SEO-лендинг и серверные маршруты; альтернатива остаётся открытой |
| `osmnx` как основа импорта | Тяжёлый исследовательский стек; для нарезки POI достаточно `pyogrio`/`pyosmium` |
| `fiona` для чтения GPKG | Нет колёс под Python 3.14; geopandas 1.x использует `pyogrio` |

## Последствия

- Версии фиксируются `uv.lock` и `package-lock.json`; мажорные обновления H3/MapLibre — отдельной задачей.
- Ядро H3 на бэкенде и фронтенде обязано совпадать (4.x): индексы 3.x и 4.x несовместимы.
- Расчёт H3-индекса при импорте означает, что смена resolution требует переимпорта — при недельном
  расписании это допустимо.
