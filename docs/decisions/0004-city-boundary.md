# ADR 0004. Источник границы города

Дата: 28.09.2026. Статус: принято.

## Контекст

`cities.boundary` — основа для генерации H3-сетки (Этап 3) и клипа POI (Этап 2). Граница нужна
не как bbox: bbox затягивает пригороды, дачи и лес, а продукт обещает «карту пустых зон» внутри города.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Nominatim, `place=city`** (выбран) | Один HTTP-запрос, готовая геометрия, ODbL, есть идентификатор relation | Публичный сервис: нужен User-Agent и ≤ 1 запроса/с |
| Nominatim, административная граница (`admin_level=6`) | Включает весь городской округ (≈ 294.6 км² по Росстату) | Приносит лес, деревни и промзоны без POI — сотни пустых ячеек вдали от города |
| Сборка полигона из PBF (`osm/osmium` area assembly) | Нет внешних сервисов, работает на уже скачанной выгрузке | Существенно сложнее: сборка мультиполигона с дырками, отдельный код и тесты |
| `bbox` как полигон | Ничего не требует | Прямо противоречит продуктовой идее: карта «размазывается» за пределы города |

## Решение

Граница берётся из **Nominatim** (`format=geojson&polygon_geojson=1`) и кэшируется в файл
`data/raw/<city>-boundary.json` вместе с лицензией и `osm_relation_id`. В БД пишется:
`boundary` (ST_Multi → MULTIPOLYGON geography), `bbox` (ST_Envelope), `center` (ST_PointOnSurface),
`boundary_source = 'nominatim'`, `osm_relation_id`.

Получение: `uv run python -m geopuls.importers.boundary --city "Томск" --out data/raw/tomsk-boundary.json`.
В тестах используется сохранённая фикстура `backend/tests/fixtures/tomsk-boundary.json` — CI не ходит в сеть.

Проверено 28.09.2026: Томск — relation 7261645 (`place=city`), площадь **176.8 км²**,
bbox 56.379–56.571 / 84.828–85.150, центр внутри полигона (`ST_Contains` = true).

## Последствия

- Полигон города меньше городского округа (177 против ≈ 295 км²): отдалённые части округа в MVP
  не попадают на карту. Это осознанный выбор — там почти нет POI. Если понадобится покрытие округа,
  добавляем вторую границу и `boundary_source = 'nominatim-admin'` (изменение данных, не архитектуры).
- Разведка покрытия (Этап 0.5) считалась по более широкому bbox (56.30–56.65 / 84.70–85.30), поэтому
  её числа немного выше, чем будут после клипа по полигону. Разница проявится при агрегации (Этап 3).
- Граница — данные, а не код: смена источника не требует миграций.
