# ADR 0005. Импорт POI: два этапа и мягкое удаление

Дата: 28.09.2026. Статус: принято.

## Контекст

Выгрузка региона — 557 МБ, один проход pyosmium с индексом координат занимает ≈ 28 минут
(замер разведки, Этап 0.5). Нужно: поддержать несколько городов, не терять данные при сбое,
уметь повторять импорт без дублей и уметь отметить «объект исчез из OSM».

## Решение

**Два этапа, которые запускаются и по отдельности:**

1. **Сканирование PBF → файл-кандидатов** (`*.poi-candidates.jsonl` рядом с выгрузкой).
   Объекты отбираются по объединению bbox **всех активных городов**, поэтому один проход
   обслуживает все города сразу: добавление второго города не удваивает время импорта.
2. **Запись в БД из файла-кандидатов** в одной транзакции: батчевый `INSERT ... ON CONFLICT`
   в `pois`, связи в `poi_categories`, мягкое удаление исчезнувших объектов, `data_versions`
   и запись в `import_runs` (`running` → `ok`/`failed`).

**Мягкое удаление — по «водяному знаку» времени БД.** В начале транзакции импорта берётся
`clock_timestamp()`, каждая вставка/обновление тоже ставит `clock_timestamp()`; объекты
с `updated_at < watermark` помечаются `is_active = false`. Почему не время Python: транзакция
Postgres использует время начала транзакции (`now()`), которое может оказаться **раньше**
момента старта импорта — тогда только что вставленные объекты попадали под «исчезнувшие».
Этот баг был пойман интеграционным тестом до выхода в прод. По той же причине при `--limit`
(режим отладки) мягкое удаление не выполняется.

## Рассмотренные альтернативы

| Альтернатива | Почему не выбрана |
|---|---|
| Staging-таблица + атомарная замена | Транзакция уже даёт нужную атомарность; отдельная таблица и `swap` усложняют схему без выигрыша при наших объёмах |
| Вырезка bbox в отдельный PBF (`osmium extract`) | Нужен внешний бинарник; при неполном наборе узлов можно сломать геометрию ways. Файл-кандидатов решает ту же задачу (повторные прогоны за секунды) без этого риска |
| Инкрементальные диффы OSM (`*.osc.gz`) | Сложнее и не нужно при недельном цикле: полный пересбор занимает минуты |
| Мягкое удаление по `id NOT IN (seen)` | Ломается при частичном импорте (`--limit`, один город) — деактивировало бы объекты, которые просто не попали в текущий прогон |

## Последствия

- Повторный импорт из файла-кандидатов — секунды; полный цикл — раз в неделю.
- Импорт идемпотентен (уникальность `osm_type + osm_id`), проверено тестом.
- Текущие ограничения зафиксированы в ТЗ (раздел 11): POI-отношения не импортируются,
  дубликаты (одинаковое название в пределах ~30 м) не помечаются флагом.
