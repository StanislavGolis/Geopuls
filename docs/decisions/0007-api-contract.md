# ADR 0007. Контракт API тепловой карты

Дата: 28.09.2026. Статус: принято.

## Контекст

Фронтенд рисует H3-сетку в MapLibre, клик по ячейке открывает список организаций. Нужны:
предсказуемый формат данных, работа с версией данных в интерфейсе, кэш и машинно-читаемые ошибки.

## Решения

**1. `/cells` отдаёт GeoJSON с полигонами ячеек, а не только центроиды.** Клиент рисует `fill`-слой
без вычислений, а `id` фичи — текстовый H3-индекс, который можно сразу передать в `/pois?cell=…`
и использовать в `h3-js`. Цена: ответ крупнее — на Томске 485 КБ raw, но **59 КБ gzip** (геометрия
гексагонов сжимается в 8 раз), время ответа 25 мс в среднем. Для больших городов есть параметр
`bbox` — фронтенд загружает видимую область.

**2. Точность координат — 6 знаков (≈ 11 см).** Ячейка res 9 имеет ребро ≈ 200 м, поэтому точность
с избытком, а размер ответа меньше, чем при полной точности double.

**3. Сжатие на уровне приложения** (`GZipMiddleware`), а не только на reverse-proxy: API должно
быть быстрым и при прямом обращении (отладка, интеграции), а не только за Caddy.

**4. Кэш через `ETag` + `Cache-Control: public, max-age=3600`.** ETag считается по составу ответа
(город, категория, разрешение, версия данных, bbox), поэтому обновление данных автоматически
инвалидирует кэш. Проверено: повторный запрос с `If-None-Match` отдаёт 304 без обращения к БД.

**5. Ошибки — RFC 9457** (`application/problem+json`) с полями `type`, `title`, `status`, `detail`,
`instance` и списком ошибок валидации. Обычный `{"detail": "..."}` FastAPI не годится: клиенту нужен
машинно-читаемый формат, а не строка.

**6. `503`, когда сетка города ещё не собрана** (не выполнен импорт или агрегация). Вариант «200 с
пустым FeatureCollection» отвергнут: интерфейс не отличит «нет данных в городе» от «данные не
собраны», а это разные сообщения для пользователя.

**7. `density_breaks` считаются на бэкенде** и отдаются в `meta` — шкала одинакова для web, PNG и
PDF-отчёта.

## Последствия

- Фронтенд не делает гео-вычислений: цвета — по `density`, классы — по `density_breaks`.
- `meta.data_version` и `meta.updated_at` есть в каждом ответе с данными: интерфейс показывает
  «данные на <дата>» (требование раздела 2.4 ТЗ).
- Публичные данные не требуют авторизации; при появлении аккаунтов (фаза после MVP) контракт
  не меняется — авторизация станет дополнительным слоем.
