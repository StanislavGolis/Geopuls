# ADR 0008. Фронтенд: раскраска из данных бэкенда

Дата: 28.09.2026. Статус: принято.

## Контекст

Нужно показать тепловую карту плотности из API: классы цветов, версия данных, честные состояния
при отсутствии данных и ошибках. Интерфейс должен работать на телефоне (раздел 4.3 ТЗ).

## Решения

**1. Классы цветов считает бэкенд, фронтенд только раскрашивает.** `meta.density_breaks` приходят
в ответе `/api/v1/cells`; фронтенд строит выражение MapLibre `step` по этим границам. Так шкала
совпадает в web, PNG- и PDF-представлениях (см. ADR 0006). Нулевые ячейки выделяются отдельным
цветом через `case` по `count == 0` — это визуальный ответ «где бизнеса нет».

**2. Ячейки рисуются из GeoJSON-полигонов ответа**, без вычислений на клиенте: `id` фичи —
текстовый H3-индекс, готовый для `/api/v1/pois?cell=…` (Этап 6) и для `h3-js`.

**3. Разрешение сетки привязано к зуму карты** (12 → res 9, ниже → res 8). Сообщает о необходимости
сменить разрешение сама карта (`zoomend`), решение о перезапросе данных принимает контейнер
(`MapExplorer`) — карта остаётся «глупым» рендерером.

**4. Состояния вместо пустого экрана:** загрузка, «нет размеченных объектов», ошибка API с кнопкой
«Повторить»; потеря связи и отсутствие собранных данных (503) показываются разными сообщениями —
пользователь должен понимать, что произошло.

**5. Честность важнее красоты.** Если в категории меньше 30 размеченных объектов, легенда
предупреждает о неполноте OSM: пустая карта может означать не отсутствие бизнеса, а отсутствие
данных. Это прямое следствие раздела 2.4 ТЗ.

## Проверки

- 30 юнит/компонентных тестов (раскраска, классы, клиент API с разбором problem+json, легенда,
  состояния, деградация без WebGL2) — запускаются в CI;
- 5 «живых» тестов против запущенного бэкенда (`GEOPULS_LIVE_API_URL`): реальные города, сетка
  Томска (>1000 ячеек), объекты найденной ячейки, разбор 404 — это проверка связки
  «компонент → HTTP → бэкенд» без моков;
- SSR-каркас страницы проверен на production-сборке: заголовок, состояние загрузки, дисклеймер
  и атрибуция присутствуют в HTML, данные подтягиваются на клиенте;
- E2E-набор Playwright (`frontend/e2e/map.smoke.spec.ts`) проверяет реальный рендеринг в Chromium:
  стиль подложки загружен, фичи теплового слоя есть в источнике и отрисованы, тайлы загружены,
  канвас занимает область карты, ошибок в консоли нет.

jsdom не умеет WebGL, поэтому юнит-тестами сам рендеринг не покрывается — за него отвечает
E2E-набор выше (история дефектов «карта пустая» и их устранение — ADR 0009).

## Уточнение от 28.09.2026 (дизайн-спека v0.2)

**1. Палитра и число классов — параметр, а не константа.** Решение 1 выше говорило «фронтенд только
раскрашивает по `density_breaks`». Уточняем: фронтенд строит столько цветов, сколько классов пришло
в `density_breaks` (`N` классов → `N` цветов из рэмпа YlOrRd, дизайн-спека §2.5), и не хардкодит ни
число классов, ни конкретные цвета «на глаз». Сегодня это 0 + 4 класса; переход на 5–6 классов —
правка бэкенда и палитры без переписывания логики раскраски (ADR 0006, уточнение от 28.09.2026).

**2. Источник визуальных решений — дизайн-спека.** Договорённость о границах ответственности:
дизайн-спека (`docs/design/design.md`) владеет визуальными токенами и компоновкой, ADR — поведением
и контрактами. При расхождении прав ADR, спека правится. Расхождения, зафиксированные ревью v0.2:

| Что в коде сегодня | Что требует спека v0.2 | ADR |
|---|---|---|
| Тёмная шапка `#0f172a` | Светлая шапка 56px (`--bg-surface`) | 0012 |
| Легенда сверху-слева, 320px | Легенда снизу-слева над строкой атрибуции, 240px | 0012 |
| Дисклеймер и футер отдельными блоками под картой | Одна постоянная строка поверх карты (OSM + OpenFreeMap + версия) | 0002 |
| `attributionControl: {compact: true}` | `attributionControl: false` + своя строка | 0002 |
| Подложка `liberty` | Подложка `positron` | 0002 |
| Нет состояний офлайн, скелетона, чипов категорий | Есть (§4.8, §6) | 0012 |
| Системные шрифты, числа не в моно | Inter + IBM Plex Mono, числа в моно | 0012 |
| Токены `--color-*` | Токены §2 спеки (`--bg-*`, `--text-*`, `--accent`, `--heat-*`) | 0012 |

**3. Доступность — часть контракта фронтенда.** Контраст ≥ AA (значения проверены в §2 спеки:
`--text-muted #5F6B76`, `--warning-text #92400E`, `--border-strong #8A95A1`), `:focus-visible` у всех
интерактивных элементов, `prefers-reduced-motion` отключает переходы, состояния объявляются через
`aria-busy`/`aria-live`, а доступный эквивалент карты (canvas) — список объектов в панели и экспорт CSV.

**Где применяется:** этапы 7a–7c (список работ — `docs/design/design.md`, §9).

## Последствия

- Смена шкалы легенды или категории не требует правок фронтенда — только данные на бэкенде.
- При появлении дополнительных слоёв (инфраструктура, фаза 2) цветовые классы придётся считать
  по каждой метрике отдельно — контракт придётся расширить (`density_breaks` уже часть `meta`).
