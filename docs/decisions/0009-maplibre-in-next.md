# ADR 0009. MapLibre в Next.js: воркер, CSS и размер канваса

Дата: 28.09.2026. Статус: принято.

## Контекст

После подключения реальных данных (Этап 5) страница открывалась, но карта была пустой: ни подложки,
ни гексагонов. Диагностика в настоящем браузере (Playwright + отладочная ссылка на объект карты)
дала три независимых дефекта, каждый из которых сам по себе оставляет экран пустым:

1. **Воркер MapLibre не загружался.** В сборке Next 16 (Turbopack) библиотека не может определить
   URL своего web-worker'а: в консоли `Worker failed to load. Check that the worker URL is correct.`
   Без воркера не парсятся ни векторные тайлы подложки, ни GeoJSON-источник — пусто и там, и там.
2. **Контейнер карты схлопывался в 0 px.** MapLibre добавляет контейнеру свой класс
   `.maplibregl-map` с `position: relative`. При равной специчности его стили перебивали наши
   `position: absolute; inset: 0` — канвас оставался 1280×300 при области 1280×597.
3. **Слои добавлялись по событию `load`**, которое не наступает, пока не загрузятся тайлы подложки.
   При недоступной подложке наш тепловой слой не появлялся вообще.

## Решения

**1. Явный URL воркера + копирование файлов воркера в `public/`.** `scripts/copy-maplibre-worker.mjs`
копирует из `node_modules/maplibre-gl/dist/` четыре файла (`maplibre-gl-worker.mjs`,
`maplibre-gl-shared.mjs` и их `-dev` версии — воркер импортирует shared-модуль, поэтому копировать
один файл недостаточно) и запускается перед `dev` и `build` через `predev`/`prebuild`.
Клиент вызывает `setWorkerUrl('/maplibre-gl-worker{,-dev}.mjs')` до создания карты, выбирая пару по
`NODE_ENV`. Файлы не коммитятся (генерируются, см. `.gitignore`) — версия всегда совпадает с пакетом.

**2. Порядок CSS и специфичность.** `maplibre-gl.css` подключается в `app/layout.tsx` **до**
`globals.css`, а наши правила растягивания записаны как `.map .map__canvas` (два класса) — так они
перекрывают служебные классы библиотеки независимо от порядка загрузки чанков.

**3. Размер канваса отслеживает `ResizeObserver`.** Контейнер меняет высоту после раскладки
(заголовок, дисклеймер, футер), поэтому на `ResizeObserver` вызывается `map.resize()`, а не только
на `zoomend`. Без этого канвас остаётся в размере, который был при создании карты.

**4. Слои добавляются по `style.load`, а не по `load`.** `style.load` наступает после разбора стиля и
не зависит от загрузки тайлов. Дополнительно: если стиль не загрузился за 8 секунд, карта
переключается на локальный минимальный стиль `FALLBACK_STYLE` (только фон) и показывает баннер
«подложка недоступна — показан только тепловой слой». Ошибки тайлов (HTTP ≥ 400 с `sourceId`)
выводятся тем же баннером, а не только в консоль.

**5. Проверка WebGL2 до создания карты.** Без WebGL2 MapLibre не рисует вообще; вместо пустого
экрана пользователь получает сообщение с подсказкой включить аппаратное ускорение.

**6. Отладочный доступ к карте — по `?debug=1`.** В dev-режиме `window.__geopulsMap` доступен всегда,
в продакшене — только при явном флаге в URL. Это то, что делает возможной проверку реального
рендеринга в E2E и разбор инцидентов «карта пустая» без гаданий.

## Проверки

`frontend/e2e/map.smoke.spec.ts` (Playwright, реальный Chromium с программным WebGL):

- карта загрузила стиль: 112 слоёв, источники `openmaptiles` и наш `cells`;
- в источнике есть фичи (`querySourceFeatures('cells')` > 0) и они отрисованы
  (`queryRenderedFeatures({layers:['cells-fill']})` > 0);
- тайлы подложки загружены (`areTilesLoaded()`), баннера о недоступной подложке нет;
- нет ошибок в консоли и ответов ≥ 400;
- канвас по высоте равен области карты (`map.resize()` работает);
- переключение категории меняет содержимое слоя.

Проверено на dev-сервере и на production-сборке (`next build` + `next start`) — пути воркера для
dev и prod различаются, поэтому обе сборки обязательны. Плюс 4 юнит-теста на деградацию без WebGL2
и минимальный стиль.

## Последствия

- Пустая карта больше не «немой» отказ: либо она рисуется, либо пользователь видит причину.
- E2E-тесты требуют запущенного стека (API + фронтенд) и Chromium (`npx playwright install chromium`),
  поэтому в CI их подключим отдельной job на Этапе 7.
- При обновлении `maplibre-gl` воркер обновляется автоматически (копируется из пакета), но имена
  файлов в `public/` нельзя переиспользовать «вручную» — они перезаписываются при каждой сборке.
