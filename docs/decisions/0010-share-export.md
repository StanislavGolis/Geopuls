# ADR 0010. Состояние в URL, список объектов ячейки и экспорт

Дата: 28.09.2026. Статус: принято.

## Контекст

Этап 6 добавляет полный пользовательский сценарий: клик по гексагону → список объектов внутри
ячейки, ссылка, которой можно поделиться, и экспорт текущего вида (PNG карты, CSV ячеек) —
разделы 4.3–4.4 ТЗ. Ключевое ограничение: всё должно работать без регистрации и без серверного
состояния, а данные нельзя «дорисовывать» — пустая ячейка обязана честно объяснять свою пустоту.

## Решения

**1. Состояние интерфейса целиком живёт в query-параметрах.** `city`, `category`, `cell`, `res`,
`zoom`, `center`. Запись — `history.replaceState` (без перерисовки карты и без засорения истории:
пользователь не должен жать «назад» после каждого перетаскивания). Чтение — на сервере:
`page.tsx` разбирает `searchParams` функцией `parseUrlState` и отдаёт состояние в `MapExplorer`,
поэтому SSR сразу содержит правильные значения (это важно для скорости и для превью ссылок).

**2. `res` — производное от `zoom`.** Сетку выбирает зум (порог 12, ADR 0008). В URL пишутся оба
параметра, но при разборе приоритет у `zoom`: руками испорченная ссылка не создаст состояние,
в котором карта на zoom 10 показывает сетку res 9.

**3. Мусор в ссылке игнорируется, а не роняет карту.** H3-индекс проверяется регуляркой (15 hex),
зум — диапазоном 1…22, центр — парой координат в допустимых пределах. Что не прошло проверку —
отбрасывается как «не задано». Это тот же принцип, что и с честными состояниями: лучше обзорная
карта города, чем белый экран.

**4. Список объектов — отдельный компонент `PoiPanel`** (`GET /api/v1/pois` с фильтром по
категории — в панели ровно те объекты, что и в тепловом слое). Панель отвечает за свои состояния:
загрузка, «в этой ячейке нет размеченных объектов» (с объяснением, что это не значит «бизнеса нет»),
ошибка с «Повторить». На экране ≤640 px панель становится «шторкой» снизу (раздел 4.3 ТЗ,
bottom sheet), на широком экране — карточкой справа.

**5. Подсветка выбранной ячейки — отдельный слой `cells-selected`.** Данные берутся из уже
загруженной коллекции `cells` (без второго запроса), поэтому подсветка мгновенная; при смене
города, категории или разрешения выбранная ячейка сбрасывается — иначе подсветка указывала бы на
сетку, которой на карте больше нет.

**6. Клик и вид карты уходят наружу колбэками** (`onCellSelect`, `onViewChange`), а не состоянием
внутри `MapView`: карта остаётся «глупым» рендерером (продолжение ADR 0008), а какое состояние
писать в URL, решает контейнер.

**7. Экспорт.**
- **PNG** — снимок канваса карты плюс подпись с источником данных и версией выгрузки. Отдавать
  «голый» снимок нельзя: лицензия ODbL и условия OpenFreeMap требуют атрибуции в любом выводе.
  Канвас читается через `getCanvas().toDataURL()`, для этого контекст создаётся с
  `canvasContextAttributes: { preserveDrawingBuffer: true }` (осознанная плата за экспорт).
- **CSV** — вся загруженная сетка по текущей категории, **включая пустые ячейки**:
  `h3,count,density_poi_per_km2,has_address_ratio,lat,lon`. «Пустые зоны» — главный ответ сервиса
  (раздел 2.4 ТЗ), выгружать только непустые ячейки значило бы выбросить половину продукта.
  Координаты — центр ячейки как среднее по вершинам кольца (для шестиугольника H3 это ровно центр,
  без добавления зависимости `h3-js`).
- Имена файлов содержат город и разрешение: `geopuls-томск-res9.png` / `.csv`.

**8. «Поделиться» копирует ссылку в буфер.** `navigator.clipboard` доступен не везде (http, старые
браузеры, локальный стенд), поэтому при отказе показываем окно с текстом ссылки — пользователь
скопирует её сам. Статус операции виден в интерфейсе: молчаливый отказ недопустим.

## Проверки

- Юнит-тесты (`vitest`): разбор и сборка URL (включая round-trip и мусор), CSV (заголовок, пустые
  ячейки, экранирование, BOM), подпись экспорта, состояния `PoiPanel`, клик по ячейке → панель + URL,
  копирование ссылки, выгрузка CSV.
- «Живые» тесты против API: `fetchPois` на самой плотной ячейке (есть название/ссылка/координаты),
  пустая ячейка → пустой список, а не ошибка, ячейка вне сетки → 404 по контракту problem+json.
- E2E (Playwright, реальный Chromium): клик по плотной ячейке открывает панель, подсвечивает её и
  пишет `cell`/`zoom`/`center` в URL; ссылка со состоянием открывает тот же кадр и панель;
  «Поделиться» кладёт ссылку в буфер; PNG скачивается с ожидаемыми размерами и весом, CSV содержит
  заголовок и всю сетку (>1000 строк).

## Последствия

- Ссылка полностью описывает картинку: `?city=tomsk&category=cafe&cell=…&zoom=13.5&center=…`.
- Состояние в URL — единственный источник правды для «что показать»: появление ещё одного параметра
  (например, слоя фазы 2) не потребует ломать существующие ссылки.
- `preserveDrawingBuffer` немного снижает производительность рендера на слабых устройствах — принято
  ради экспорта; если появится жалоба на FPS, экспорт можно перевести на `map.once("render")` без
  постоянного буфера.
