# ADR 0014. Метрики слоёв: площадь, длина и склейка дубликатов

Дата: 29.09.2026. Статус: принято и реализовано (Этап 9).

Связано: ADR 0006 (агрегация H3), ADR 0013 (слои карты), разведка
`docs/recon/2026-09-29-tags-for-layers.md`, ТЗ §3, §6.1, §11.

## Контекст

ADR 0013 ввёл слои, но оставил открытым вопрос: чем измеряются слои, которых раньше не было. Слой
конкурентов считал «штуки на км²» — этого достаточно для POI, но не для жилой застройки (важна
площадь), не для пешеходных путей (важны километры) и не для остановок (одну остановку в OSM часто
рисуют тремя объектами).

Разведка показала конкретные числа: 16 978 полигонов жилья (90 км²), 786 км пешеходных путей,
2 065 объектов-остановок при реальном их числе в полтора-два раза меньше.

## Решения

**1. Тип метрики задаёт слой, а не агрегатор.** В каталоге (`geopuls.layers_catalog`) у слоя указан
`metric_kind`: `density`, `area_share` или `length`. Агрегатор читает его и считает значение
соответствующим способом; единица измерения и подпись живут там же и попадают в API, легенду и экспорт.

**2. Геометрия объектов хранится отдельно от точки.** `pois.geometry` (миграция 0004) — линия или
полигон для way; `pois.location` остаётся точкой: по ней идёт привязка к ячейке, список объектов и
фильтр по полигону города. Дублировать нельзя, но и заменить точку геометрией тоже нельзя: у 13792
объектов конкурентов геометрии нет вовсе.

**3. Площадь и длина считаются пересечением с полигоном ячейки, а не по центроиду.** Для этого
`city_cells.boundary` хранит полигон ячейки, а PostGIS пересекает его с геометрией объекта. Причина
продуктовая: большой жилой квартал, отнесённый к одной ячейке по центроиду, показал бы плотную
застройку в одном гексагоне и пустоту в соседних — карта соврала бы в самом заметном месте.

Цена: `ST_Intersection` дороже простого `GROUP BY`, но агрегация батчевая (раз в неделю), и GiST-индексы
по обеим колонкам держат время в секундах.

**4. Склейка дубликатов — в агрегаторе, а не в импорте.** Остановки, стоящие ближе 30 м, считаются
одной; радиус берётся из каталога (свойство слоя, а не общая настройка). Из группы остаётся объект с
наименьшим OSM id — как правило, более старая и более стабильная запись.

Почему не в импорте: склейка — правило отображения. Его можно пересмотреть (10 м? 50 м?) и пересобрать
агрегаты за минуту, не переимпортируя 557 МБ выгрузки.

**5. Импортёр сопоставляет категории всех слоёв.** Раньше он знал только восемь категорий конкурентов;
теперь — каталог целиком (`ALL_CATEGORIES`). Иначе слои Этапа 9 остались бы без данных, а расхождение
«слой есть, данных нет» выглядело бы как пустой город.

**6. Пустая ячейка и «нет данных» — разные вещи.** Если слой собран не по всей сетке, API отдаёт
`null`, а не ноль: ноль утверждает «объектов здесь нет», `null` — «мы не знаем» (введено в ADR 0013,
здесь подтверждено для новых метрик).

## Альтернативы

| Альтернатива | Почему не выбрана |
|---|---|
| Считать площадь по центроиду | Крупные `landuse`-полигоны дают ложную картину: один гексагон «застроен», соседние пусты |
| Считать площадь и длину в Python по выгрузке | Агрегатор читает БД, а не PBF; пришлось бы тащить геометрию через весь пайплайн и терять единый источник истины |
| Хранить площадь/длину готовыми числами в `pois` | Не решает главного: доля площади ячейки требует пересечения с ячейкой, а не общей площади объекта |
| Склеивать остановки при импорте | Правило отображения попало бы в данные: передумав, пришлось бы переимпортировать выгрузку |
| DBSCAN в PostGIS (`ST_ClusterDBSCAN`) | Кластеризация в градусах, а не метрах: на широте Томска радиус искажается в 1.8 раза, и настраивать его пришлось бы под широту города |
| Метрика `presence` для парковок | Парковки уже выражены долей площади: `0` = «нет парковки», отдельный тип метрики не нужен |

## Последствия

- Миграция `0004`: `pois.geometry`, `city_cells.boundary` + GiST-индексы. Требуется переагрегация всех
  городов: границы ячеек заполняются при сборке сетки.
- Чтобы новые слои наполнились данными, нужен переимпорт выгрузки: категории слоёв появились после
  последнего импорта. Команда: `uv run python -m geopuls.refresh --city tomsk --pbf <выгрузка>.osm.pbf`.
- В `cell_stats` по-прежнему только слой конкурентов (совместимый путь чтения). Остальные слои живут
  только в `cell_metrics` — это осознанно: `cell_stats` — legacy-контракт `/api/v1/cells`.
- Метрика `length` считается в километрах на ячейку. Площади ячеек различаются до 1.99×, поэтому
  сравнивать соседние ячейки по километрам можно, а по «км/км²» — точнее; вопрос откроется, если
  пешеходный слой станет базовым для решений.
