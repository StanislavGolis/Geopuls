## 1. Общая концепция

Сервис — **деловой инструмент для анализа городской среды**, не дашборд и не интерактивная игрушка. Ключевой принцип: **карта — это продукт, интерфейс — это обслуживание карты**. Всё, что не помогает понять карту, — убирается.

**Ключевые принципы:**
- Карта занимает **≥80% экрана** на десктопе и **весь экран** на мобильном.
- Интерфейс **не перекрывает карту** без необходимости — только header сверху, легенда в углу, панель POI по клику.
- Тепловая шкала — **честная**, классы считаются на бэкенде (ADR 0006), фронт только раскрашивает.
- «Пустые зоны» — **видимый продукт**, а не отсутствие данных. Пустые ячейки всегда показаны (тонкой обводкой).
- Дисклеймер «данные OSM могут быть неполны» — **часть интерфейса**, не скрытая надпись в футере.

**Тема:** только светлая. Тёмная — не в MVP.

## 2. Цветовая палитра

### 2.1. Базовые цвета

```
--bg-canvas:      #F7F8FA   (фон страницы, светлый тёплый серый)
--bg-surface:     #FFFFFF   (фон карточек, панелей, header)
--bg-subtle:      #EEF0F4   (ховер, неактивные кнопки, скелетоны)
--bg-overlay:     rgba(15, 20, 25, 0.5)  (затемнение под модалкой/шторкой)
```

### 2.2. Текст

```
--text-primary:   #0F1419   (основной, почти чёрный; на белом 18.5:1)
--text-secondary: #4A5560   (вторичный, серо-синий; на белом 7.6:1)
--text-muted:     #5F6B76   (подписи, метаданные; на белом 5.45:1, на --bg-subtle 4.78:1 — проходит AA)
--text-inverse:   #FFFFFF   (на тёмных элементах)
```

**Проверено:** значения посчитаны по WCAG 2.1. В v0.1 `--text-muted` был `#8A95A1` — это 3.05:1 на
белом, то есть провал AA для кегля 11–12px (им подписаны метаданные и строка атрибуции). Не менять
`--text-muted` на более светлый, не проверив контраст.

### 2.3. Акценты

```
--accent:         #2563EB   (синий, кнопки, ссылки, активные элементы; на белом 5.17:1)
--accent-hover:   #1D4ED8   (ховер)
--accent-subtle:  #DBEAFE   (фон активного пункта, подсветка)
--danger:         #DC2626   (ошибки; на белом 4.83:1)
--warning:        #D97706   (иконки, рамки, акцент плашки — НЕ текст)
--warning-text:   #92400E   (текст предупреждений; на плашке #FEF3C7 6.37:1)
--warning-bg:     #FEF3C7   (фон плашки предупреждения)
--success:        #059669   (успешные состояния, редкие)
```

**Почему два «warning»:** в v0.1 `--warning #D97706` использовался и как текст — это 3.19:1 на белом
и 2.86:1 на плашке, то есть провал AA для 11px. Для текста берём `--warning-text`, для иконок и рамок
остаётся `--warning`.

### 2.4. Границы

```
--border:         #E5E8EC   (декоративные разделители; к компонентам не применяется)
--border-strong:  #8A95A1   (границы интерактивных элементов, focus; на белом 3.05:1 — проходит
                             порог 3:1 для элементов интерфейса)
```

**Разделение:** `--border` — только декоративные линии (разделители, фон-границы карточек). Для
всего, что пользователь нажимает (кнопки, селекты, чекбоксы, границы полей), обязателен
`--border-strong`: у v0.1 `#CBD2D9` давал 1.53:1 против белого.

### 2.5. Тепловая шкала (ключевой элемент)

Шкала — **YlOrRd** (Yellow → Orange → Red), классическая для «горячо = много». Инвертировать не нужно: предприниматель ожидает, что красное = плотное.

Палитра — **дискретная и зависит от числа классов**, которое задаёт бэкенд (в `density_breaks`
приходят границы, у нас сейчас 0 + 4 класса = 5 значений; см. ADR 0006). Правило: для `N` классов
берём `N` цветов из шестиступенчатого рэмпа равномерно — так дизайн не ломается при переходе на 5–6
классов, а шкала web/PNG/CSV остаётся одной и той же.

```
Пустая ячейка (0 объектов):
--heat-empty:        #E6EAEF   (заливка, opacity 1)
--heat-empty-stroke: #7C8794   (обводка 1px; против светлой подложки ≈3.3:1)

Рэмп плотности (6 ступеней):
--heat-1: #FEF3C7   --heat-2: #FDE68A   --heat-3: #FCD34D
--heat-4: #F59E0B   --heat-5: #EA580C   --heat-6: #B91C1C

Сегодня (4 класса): --heat-1, --heat-3, --heat-4, --heat-5
(6 классов: все шесть — переход запланирован, но не включён, пока на данных получаются пустые классы)
```

**Прозрачность (уточнено 28.09.2026 — по факту жалобы на нечитаемую карту):** сплошная заливка пустых
ячеек закрывает подложку: пустых ячеек в городе 78%, и они накрывали карту ровным серым полотном.
Замер (пробник рисовал канвас со слоем и без него и считал среднее осветление тёмных деталей
подложки — улиц, подписей, контуров):

| Вариант заливки | Осветление деталей подложки | Среднее отличие картинки |
|---|---|---|
| пусто 1.00 / цветные 0.75 (v0.1) | 8.3 | 5.4 |
| **пусто 0.15 / цветные 0.45 (принято)** | **2.3** | **2.4** |
| пусто 0.00 / цветные 0.50 | 1.4 | 2.4 |

Принято: **пустые ячейки — заливка `opacity 0.15` + обводка `rgba(124, 135, 148, 0.6)`**, непустые —
`opacity 0.45`. Смысл «здесь размеченных объектов нет» несёт сетка контуров и легенда, а точные
значения — панель объектов и CSV. Значения защищены E2E-проверкой: заливка не должна вернуться к
сплошной (`fill-opacity` пустых ≤ 0.2, непустых ≤ 0.5).

**Честное ограничение:** заливкой пустую ячейку от светлой подложки не отделить (контраст ≈1.1), а
плотная заливка не помогает, а вредит — поэтому «пусто» показываем контуром, легендой и панелью.

**Обязательная проверка:** скриншот Томска (кафе, res 9) на итоговой подложке — убедиться, что пустые
ячейки видны, а классы плотности различаются. Пока проверка не пройдена на реальной подложке, шкала
считается неподтверждённой.

### 2.6. Запреты

- Градиенты (кроме тепловой шкалы — она дискретная).
- Тени (`box-shadow`) — только у **всплывающих** элементов (легенда, панель POI, модалки, меню) и
  `focus-ring`, одна мягкая тень `--shadow-raised: 0 2px 8px rgba(15, 20, 25, 0.12)`. У карточек в
  потоке тени нет: белая панель без тени на светлой карте не читается, а тень «для красоты» запрещена.
- Скругления > 8px у карточек и кнопок (нижняя «шторка» на мобильном — тоже 8px).
- Насыщенные цвета фонов у больших областей.

## 3. Типографика

### 3.1. Шрифты

```
Интерфейс:         Inter (400, 500, 600, 700)
Числа и данные:    IBM Plex Mono (400, 500) — H3-индексы, координаты, счётчики
```

**Почему IBM Plex Mono, а не JetBrains Mono:** в DREDGE это был «технический архив». Здесь — деловой инструмент. Plex Mono мягче, лучше читается рядом с Inter, не создаёт «хакерского» настроения.

Подключение: self-host через `next/font/local` (2 файла woff2 на начертание).

### 3.2. Размеры

```    
Заголовок страницы:  20px / 600 / -0.01em
Заголовок секции:    15px / 600 / uppercase, letter-spacing 0.04em
Основной текст:      14px / 400 / line-height 1.5
Метаданные:          12px / 400 / --text-muted
Числа и H3:          12px / 500 / IBM Plex Mono
Кнопки:              14px / 500
Подписи на карте:    11px / 500
```

### 3.3. Правила

- Все **числа, H3-индексы, координаты, размеры** — только IBM Plex Mono.
- **Uppercase** — только для меток секций (`ЛЕГЕНДА`, `ОБЪЕКТЫ`), не для кнопок и не для заголовков.
- **Жирность** — только 400, 500, 600. 700 — только для логотипа.
- **Никаких курсивов.**
- Кегль 11px — только для uppercase-меток и подписей на карте; числа, счётчики и H3-индексы — 12px
  (в v0.1 H3-индекс в §4.5 был 11px, что противоречило §3.2 — оставлено 12px).
- Шрифты подключаем self-host (`next/font/local`), это внешние зависимости: лицензии Inter и IBM Plex
  Mono (OFL) кладём в репозиторий рядом со шрифтами, чтобы не потерять право на распространение.

## 4. Ключевые компоненты

### 4.0. Навигация: вкладки-сцены (30.09.2026)

Интерфейс разделён на четыре вкладки; вкладка — это **сцена**: своя основа карты, своя панель управления
в шапке и своя панель данных. Обоснование — ADR 0016, отказ от административных районов — там же.

```
┌──────────────────────────────────────────────────────────────────────┐
│  ГЕОПУЛЬС   [Томск ▾]                        [Поделиться] [↓ ▾]       │  ← header, 56px
├──────────────────────────────────────────────────────────────────────┤
│ [Конкуренты] [Инфраструктура] [Инструменты] [Город]   Категория [Кафе ▾] │  ← панель сцены, 40px
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│                              КАРТА                                   │
│                                                                      │
├──────────────────────────────────────────────────────────────────────┤
│ Данные © OpenStreetMap · выгрузка 27.09.2026 · fixthemap             │
└──────────────────────────────────────────────────────────────────────┘
```

| Вкладка | Что на карте | Панель сцены | Панель данных |
|---|---|---|---|
| **Конкуренты** | плотность выбранной категории | категория (селект на десктопе, чипы на мобильном) | карточка зоны: организации + числа включённых слоёв |
| **Инфраструктура** | выбранный слой OSM (остановки, парковки, точки притяжения, жильё, промзоны, пешеходные пути) | выбор показателя | карточка зоны: значения слоёв |
| **Инструменты** | конкуренты — фон для измерений | категория + выбор инструмента | радиус вокруг точки или сравнение зон |
| **Город** | конкуренты | — | сводка по данным города |

**Навигация.** Вкладка — кнопка 13px; активная получает фон `--bg-surface`, границу `--border` и вес 600;
неактивная — только текст `--text-secondary` и подложку `--bg-subtle` при наведении. Полоса вкладок
прокручивается по горизонтали и не показывает полосу прокрутки (на телефоне вкладки не помещаются
целиком).

**Что осталось в шапке.** Логотип, выбор города, «Поделиться» и «Экспорт». Кнопок «Сравнить», «Радиус» и
«Профиль города» больше нет: они стали вкладкой и её инструментами, иначе один и тот же экран открывался
бы двумя способами.

**Правила сцены.**

- Карта одна: экземпляр MapLibre создаётся при загрузке, вкладка меняет пресет (основу, наложения, круг,
  контуры зон).
- Одна панель данных на вкладку: радиус, сравнение и профиль больше не открываются одновременно.
- Выбор пользователя не сбрасывается при переходах: категория конкурентов и показатель инфраструктуры
  живут отдельно от активной вкладки.
- Режимы, перехватывающие клик по карте (сравнение и радиус), выключаются при уходе с «Инструментов»:
  на другой вкладке клик открывает карточку зоны.

**Мобильный.** Те же четыре вкладки, категория — чипами (селект скрыт). Цель мобильной версии —
посмотреть информацию: карта, легенда, карточка зоны, сводка. Инструменты (радиус, сравнение) доступны,
но не оптимизируются под малый экран: сравнение зон на телефоне читается как таблица с горизонтальной
прокруткой.

### 4.1. Header (десктоп)

Высота — **56px**. Фон `--bg-surface` (светлый!), нижняя граница `--border`. Три зоны:

> **Важно для реализации:** сейчас в коде шапка тёмная (`#0f172a`) — это остаток каркаса Этапа 0.
> Спека требует светлую шапку: правило «только светлая тема» и «интерфейс не конкурирует с картой».

```
┌────────────────────────────────────────────────────────────────┐
│  ГЕОПУЛЬС     [Томск ▾]  [Кафе ▾]          [Поделиться] [↓ ▾] │
└────────────────────────────────────────────────────────────────┘
```

- **Логотип** — текст `ГЕОПУЛЬС`, Inter 700, 16px, letter-spacing 0.08em.
- **Селекторы города и категории** — дропдауны, 200px и 160px. Стиль — вторичная кнопка.
- **Кнопки справа** — «Поделиться» (иконка link) и «Экспорт» (иконка download + меню «PNG / CSV»,
  см. §4.9). Вторичные кнопки, 36px высотой.
- **Версию данных и разрешение сетки** в шапке не показываем: версия — в постоянной строке (§4.7),
  разрешение — в легенде (§4.4). В v0.1 эти данные жили в шапке, но там им тесно и они мешают.
- **Никаких** уведомлений, профиля, меню — этого нет в MVP.

### 4.2. Кнопки

### 4.3. Карта

Занимает всё пространство под header (и над постоянной строкой атрибуции, §4.7).

- Подложка: OpenFreeMap, стиль **`positron`** — светлый, чтобы не конкурировать с тепловой картой
  (ADR 0002; альтернативы `liberty`/`bright` подключаются переменной `NEXT_PUBLIC_BASEMAP_STYLE_URL`).
- Тепловой слой — поверх подложки, под UI-элементами.
- Слой выбранной ячейки — поверх остальных ячеек, обводка `--accent` 2px; подсветка и список объектов
  в панели синхронны (выбрали ячейку → открылся список, закрыли список → подсветка снялась).
- Attribution MapLibre — контрол **отключён** (`attributionControl: false`): текст атрибуции показан в
  постоянной строке (§4.7), это требование лицензий ODbL и OpenFreeMap.
- Клик по пустому месту карты снимает выбор ячейки (как закрытие панели крестиком).

### 4.4. Легенда

Плавающий блок, **левый нижний угол карты**, но **над постоянной строкой атрибуции** (§4.7) —
отступ 16px, между легендой и строкой тоже 16px. Иначе легенда накрывает строку, а на мобильном —
и атрибуцию.

```
┌────────────────────────────────┐
│ ПЛОТНОСТЬ, POI / КМ²           │
│ ░░░ 0        пусто             │
│ ███ до 25.6                    │
│ ███ 25.6 – 42.7                │
│ ███ 42.7 – 59.8                │
│ ███ более 59.8   высокая       │
│                                 │
│ res 9 · объектов в категории 412│
└────────────────────────────────┘
```

- Фон `--bg-surface`, рамка `--border`, скругление **8px**, паддинг 12px, ширина **240px**,
  тень `--shadow-raised` (плавающий элемент).
- Заголовок `ПЛОТНОСТЬ, POI / КМ²` — uppercase, 11px, `--text-muted`.
- **Границы классов — из `meta.density_breaks`** и показываются как **плотность** (POI/км²) с одним
  знаком после запятой, а не как количество объектов: в v0.1 в макете стояли «1–3, 4–8, 9–15» —
  это читается как число объектов и вводит в заблуждение. Единицы (`POI / км²`) обязательны.
- Строка `res N · объектов в категории M` — IBM Plex Mono 12px, `--text-muted`. Разрешение сетки
  показываем здесь (в v0.1 его место не было определено, в коде он жил в шапке).
- Нулевой класс подписан словом «пусто» и обводкой, как в §2.5.
- Если объектов < 30 — плашка `--warning-bg` под легендой с текстом `--warning-text` 11px:
  «Мало данных OSM — карта может быть неполной».
- Сноска о честности данных — в легенде под классами: «Только объекты, размеченные в OpenStreetMap»
  (в постоянной строке уже четыре элемента, дублировать лицензии и дисклеймер в одном месте не нужно).

### 4.5. Панель POI (десктоп)

Появляется справа при клике по ячейке, ширина **360px**, отступ 16px, максимум 60vh.

```
┌─────────────────────────────────────┐
│ ОБЪЕКТЫ В ЯЧЕЙКЕ      12 объектов [×] │
│ 8928308280fffff                     │
├─────────────────────────────────────┤
│ Кофейня «Сибирь»                    │
│ пр. Ленина, 54                      │
│ Кофейни и кафе · OpenStreetMap      │
│                                     │
│ Coffee Like                         │
│ ул. Красноармейская, 101            │
│ Кофейни и кафе · OpenStreetMap      │
└─────────────────────────────────────┘
```

- H3-индекс — IBM Plex Mono, 12px, `--text-muted`.
- Список — плоский, без карточек. Каждый элемент: название (14px, 500; если названия нет — бренд,
  если и его нет — «Без названия»), адрес (12px, `--text-muted`), категории и **ссылка на
  OpenStreetMap** (11–12px, `--accent`). Ссылка обязательна: это способ пользователя проверить и
  исправить данные (ADR 0010, лицензия ODbL).
- Ссылка открывается в новой вкладке с `rel="noreferrer"`.
- **Точка-маркер на карте** (в v0.1 — «точка перед названием»): это отдельная задача — слой точек
  для объектов выбранной ячейки. В MVP показываем панель и подсветку ячейки; в макете точку
  оставляем как «планируется», чтобы не считать её реализованной.
- Состояния панели: загрузка («Загружаем объекты…»), пусто (текст ниже), ошибка API с кнопкой
  «Повторить» (см. §4.8). Если объектов больше лимита ответа — строка «Показано N из M».
- Плюрализация счётчика: «1 объект», «2 объекта», «12 объектов» (не «12 шт.» и не «12 объект»).
- Пусто: «В этой ячейке нет размеченных объектов. Это не значит, что бизнеса здесь нет — данные OSM
  могут быть неполными».

### 4.6. Панель POI (мобильный)

Bottom sheet. Появляется снизу, высота 50vh, ручка для свайпа сверху.

- Анимация — 250ms, ease-out.
- Заголовок закреплён сверху, список скроллится.
- Закрытие — **крестик**; свайп вниз — факультативно (отдельная задача, в MVP не обязателен:
  крестик доступнее для скринридеров и не конфликтует с жестами карты под шторкой).
- Нижний отступ учитывает `env(safe-area-inset-bottom)` (жестовая полоса iOS).
- Шторка не должна перекрывать постоянную строку атрибуции: строка остаётся видимой над шторкой.

### 4.7. Дисклеймер о данных и атрибуция

**Постоянная строка внизу карты** (не в футере страницы — это важно, чтобы пользователь видел её всегда):

```
Данные © OpenStreetMap contributors · выгрузка 27.09.2026 · Подложка: OpenFreeMap © OpenMapTiles · Сообщить об ошибке
```

- 11px, `--text-muted` (с v0.2 это `#5F6B76` — прежний `#8A95A1` не проходил AA), IBM Plex Mono для
  даты и названия выгрузки.
- Фон — полупрозрачный белый `rgba(255, 255, 255, 0.85)`, чтобы читалось поверх карты; высота — одна
  строка, на мобильном переносится на две.
- **В строке три обязательных упоминания:** OSM (данные), OpenFreeMap/OpenMapTiles (подложка),
  ссылка на `openstreetmap.org/fixthemap`. В v0.1 подложка в строке отсутствовала — это лицензионный
  пробел: атрибуция подложки обязана быть видна, а компактный контрол MapLibre её прячет.
- Из-за этой строки контрол атрибуции MapLibre **отключается** (`attributionControl: false`) —
  иначе внизу экрана конфликтуют три элемента: легенда, строка и атрибуция.
- Футер страницы (`Подложка: … · ГЕОПУЛЬС, 2026`) в v0.2 не нужен: его содержимое переехало в строку,
  а карта по §1 должна занимать экран целиком.

### 4.8. Состояния загрузки, пустоты и ошибок

**Загрузка ячеек:** поверх карты, по центру, скелетон — три пульсирующих гексагона (пульсация 1s,
ease-in-out, единственная разрешённая loop-анимация, см. §5). Контейнер карты получает `aria-busy="true"`.
Текстовое «Загружаем…» остаётся как `aria-label` для скринридеров.

**В городе/категории нет размеченных объектов (совсем):** на весь экран — карточка «В этом городе нет
размеченных объектов категории. Мы не показываем выдуманные данные» + подсказка попробовать другую
категорию. Это отдельное состояние от «мало данных»: пустая карта честно объясняет, что объектов в OSM нет.

**503 (данные для города ещё не собраны):** карточка с иконкой, текст «Данные для этого города ещё не
собраны. Мы работаем над этим», кнопка «Выбрать другой город».

**Ошибка API:** та же карточка, но с кнопкой «Повторить». Текст — `title`/`detail` из ответа
(problem+json), но **без технических подробностей** (команды импорта, имена таблиц): они нужны
оператору, а не предпринимателю. Технику показываем только в логах и в локальном окружении.

**Нет связи (офлайн):** баннер вверху карты «Нет связи с сервисом — показаны последние загруженные
данные» + данные из последнего успешного ответа (требование §4.3 ТЗ). Без сохранённых данных — то же,
что «ошибка API».

**Мало данных в категории (< 30 объектов):** карта показывает ячейки, легенда подсвечивает
предупреждение (плашка `--warning-bg`/`--warning-text`).

**Панель POI:** загрузка («Загружаем объекты…»), пусто (§4.5), ошибка с «Повторить», обрезка лимитом
(«Показано N из M»).

### 4.9. Экспорт

**PNG:** кнопка скачивает снимок карты с подписью-атрибуцией (см. ADR 0010). Имя файла —
`geopuls-томск-res9.png`.

**CSV:** то же имя, `.csv`. Включая пустые ячейки.

- В шапке одна кнопка **«Экспорт»** (иконка download) с меню «PNG карты» и «CSV ячеек»: три отдельные
  кнопки в шапке (как в промежуточной реализации) перегружают её, а в макете v0.1 место для двух
  форматов не определено.
- Меню доступно с клавиатуры: `Enter`/`Space` открывают, стрелки перемещают, `Esc` закрывает.
- Кнопка **«Поделиться»** (иконка link) — копирует ссылку; на мобильном, если доступен
  `navigator.share`, показываем системное меню «поделиться» (дополнение v0.2).
- На мобильном кнопки — **только иконки** (36×36, тач-цель ≥44px с учётом отступа).
- Кнопки вторичные; пока данные не загружены — `disabled`.

### 4.11. Панель слоёв (Этап 8, 29.09.2026; переработана 30.09.2026)

Панель отвечает на два вопроса: «чем красится карта» и «что ещё известно про эту ячейку». Место —
левый верхний угол карты, 260px, светлая карточка с `--shadow-raised`; легенда остаётся внизу (§4.4),
поэтому эти два блока не спорят за один угол.

**Состав панели (сверху вниз):**

1. **Основа карты** — фиксированная строка, а не выбор: карту всегда красит слой «Конкуренты» в
   выбранной категории. Категорию меняют в шапке (§4.2); в панели переключателя нет, потому что
   «где спрос, а где пусто» — главный ответ сервиса, и он не должен зависеть от случайного клика.
2. **Дополнительно в ячейке** — чекбоксы слоёв (население, транспорт, парковки, пешеходные пути…).
   Слой ничего не рисует: его числа появляются в карточке выбранной ячейки (§4.5) рядом с её
   объектами. Под включённым слоем подписаны метрика и единица; если данных по слою в сетке нет,
   там прямо сказано «данные ещё собираются» — обещать числа, которых нет, нельзя.
3. **Активные слои** — по строке на включённый слой: имя, метрика и единица («Плотность, POI/км²»),
   предупреждение «собрано по N из M ячеек» при неполном покрытии и атрибуция источника.

**Почему слои больше не рисуются на карте.** Вариант «до двух контуров поверх заливки» проверялся на
реальных данных: несколько показателей, каждый со своей шкалой и цветом, давали кашу, а карта
переставала отвечать на главный вопрос. Читаемость важнее полноты: одна заливка (конкурентная
плотность) плюс числа по клику — два уровня детализации одной и той же мысли, а не пять разных карт.

**Клик по гексу** даёт две вещи: точки объектов **выбранной категории** внутри ячейки (карта показывает,
где именно стоят конкуренты, а не всё, что размечено в OSM) и числа включённых дополнительных слоёв в
карточке ячейки. Список объектов в панели фильтруется той же категорией — карта и список обязаны
показывать одно и то же.

**Правила честности:**

- Метрика называется словами (`metric_kind` → «Плотность», «Доля площади», «Плотность населения»):
  одну и ту же лестницу классов нельзя читать одинаково для «штук» и «человек на км²».
- Неполное покрытие слоя показывается явно: «нет данных» — это не ноль.
- Атрибуция источника видна и в панели, и в постоянной строке (§4.7), и в экспорте (§4.9).

**Состояние в ссылке:** `base=competitors:cafe&overlays=population,transport`. Параметр `overlays`
теперь означает «слои, числа которых показываются в карточке ячейки» (раньше — контуры на карте).
Параметр `category` оставлен рядом с `base` для совместимости: ссылки, разошедшиеся до появления
слоёв, обязаны открывать ту же карту.

**Мобильный (§6):** панель свёрнута в кнопку «Слои» в левом верхнем углу карты — как легенда;
тап раскрывает карточку, повторный тап сворачивает. Тач-цели ≥ 44px.

**Инварианты, проверяемые тестами:** основа карты одна и в интерфейсе не переключается; основа не
предлагается как дополнительный слой; включённый слой без данных помечен «данные ещё собираются»;
числа слоя в карточке ячейки берутся из той же колонки ответа `/api/v1/map`.

### 4.12. Профиль города (план развития, этап 1, 30.09.2026)

Экран, отвечающий на вопрос «что это за город» за десять секунд: менеджер по региональному развитию
приезжает из другого города и не знает контекста — «Томск это где, 77% пустых ячеек это норма?».

**Где живёт.** Модальная карточка поверх карты (не отдельный маршрут): открывается кнопкой «Профиль
города» в шапке и состоянием `profile=1` в ссылке — сводкой делятся, а не открывают её заново.

**Состав (сверху вниз):**

1. Название города и регион; подпись «сводка по данным OpenStreetMap».
2. Факты: площадь, разрешение сетки, дата данных, число объектов в категориях.
3. Охват данных: ячеек всего, с объектами, доля пустых — с прямым объяснением, что пустая ячейка
   значит «нет размеченных объектов», а не «нет бизнеса» (ТЗ §4.2).
4. Категории: название, число объектов, доля от общего.
5. Слои: метрика с единицей, покрытие (непустых из покрытых), максимум — те же правила, что в легенде.
6. Источники: лицензия, версия выгрузки, атрибуция.
7. Оговорка внизу: «наблюдения по данным, а не рекомендации» (ADR 0015).

**Правила честности:** у каждой цифры есть единица измерения; числа считает бэкенд
(`/api/v1/meta/cities/{slug}/profile`), интерфейс их не складывает — иначе сводка разойдётся с картой;
рекомендаций и баллов нет.

**Мобильный:** карточка занимает экран, прокручивается внутри, закрывается крестиком или Esc.

### 4.13. Сравнение зон (план развития, этап 2, 30.09.2026)

Менеджер не смотрит зоны по одной: ему нужно сравнить 2–5 площадок и выбрать. Экран отвечает на это
таблицей «зона против зоны» — той, что можно вставить в презентацию.

**Как попадают зоны.** Кнопка «Сравнить» в шапке включает режим: клик по гексу добавляет зону, повторный
клик убирает (до пяти). Пока зон меньше двух, панель объясняет, что делать. Список уезжает в ссылку
(`compare=<h3>,<h3>`) — сравнением делятся так же, как видом карты.

**Что в таблице.** Строки — показатели, колонки — зоны. Первой идёт плотность конкурентов (то, с чем
сравнивают в первую очередь) и число объектов, дальше — все слои с метрикой и единицей измерения. Внизу
оговорка: «нет данных» — это не ноль, а решение о зоне принимает человек.

**Чего в таблице нет.** Вердиктов «перегрев / мало» и суммарных баллов: единицы измерения разные
(плотность, доля площади, километры), складывать их в один балл — значит выдавать предположение за
измерение (ADR 0015).

**Поведение на карте.** Все зоны сравнения подсвечиваются контуром, чтобы таблица и карта говорили об
одном. В режиме сравнения клик не открывает карточку объектов — иначе клик по третьей зоне затирал бы
карточку, которую в это время читают.

**Мобильный:** панель занимает низ экрана, таблица прокручивается по горизонтали.

### 4.14. Радиус вокруг точки (план развития, этап 3, 30.09.2026)

Менеджер меряет расстояние руками: «сколько конкурентов в пяти минутах от этого адреса». Гекс на такой
вопрос отвечает неточно (его границы не совпадают с кругом), поэтому радиус — отдельный режим.

**Как ставится точка.** Кнопка «Радиус» в шапке включает режим, и клик по карте ставит точку — там, куда
попал пользователь, а не в центре гекса. Пока точки нет, внизу видна подсказка «кликните по карте»: без неё
включённый режим выглядит как «ничего не произошло».

**Что видно на карте.** Круг радиуса — заливка 12% и штриховой контур акцентным `#b45309`, плюс точка центра.
Радиус круга — тот же, которым посчитан ответ, поэтому картинка и числа не могут разойтись.

**Что в панели.** Заголовок «Что вокруг точки», строка «Радиус 500 м · Кофейни и кафе», переключатель радиуса
(100 / 300 / 500 / 1000 / 2000 м) и таблица: строка — слой, колонки — «В радиусе» и «Ближайший». Числа с
окончаниями («3 объекта»), отсутствие объектов — словами «нет в радиусе» вместо нуля, ближайший — с именем
и расстоянием («Baba Roma — 105 м»). Внизу — координаты точки и оговорка про наблюдения (ADR 0015).

**Чего в панели нет.** Процентов и долей площади: в круге мы их не считаем, а «число объектов» под видом
«доли площади» — это подмена. Вердиктов и советов здесь нет по той же причине, что и в сравнении зон.

**Взаимодействие режимов.** «Сравнить» и «Радиус» взаимоисключающие: оба забирают клик по карте. Включение
одного закрывает другой вместе с его точкой.

**Ссылка.** `around=56.48470,84.94820&radius=300`; радиус 500 м — значение по умолчанию, в ссылку не
попадает. Мусор в координатах или радиусе игнорируется, а не роняет карту.

**Мобильный:** панель — снизу во всю ширину, переключатель радиуса прокручивается по горизонтали.

## 5. Анимации

Длительности — **150–250ms**, easing — `ease-out` для появления, `ease-in` для скрытия. Никаких пружин и bounce.

Ограничение «не длиннее 300ms» относится к **интерфейсным** переходам. Движение камеры карты
(`fitBounds` при выборе города) — не UI-анимация: 400–600ms там нормально и не считается нарушением.

При `prefers-reduced-motion: reduce` все переходы (кроме мгновенной смены состояния) отключаются:
`transition: none`, скелетон-пульсация выключается. Это требование доступности, а не «украшение».

| Что | Длительность | Эффект |
|---|---|---|
| Появление панели POI | 200ms | slide-in справа (desktop) / снизу (mobile) |
| Наведение на кнопку | 120ms | смена фона/границы |
| Подсветка выбранной ячейки | 150ms | fade-in обводки |
| Смена категории | 250ms | fade-out старого слоя → fade-in нового |
| Появление предупреждения в легенде | 200ms | fade-in |

**Запрещено:** анимации длиннее 300ms (кроме движения камеры карты), любые loop-анимации, кроме
пульсации скелетонов (1s, ease-in-out).

## 6. Мобильная версия

**Header** — 52px, только логотип и город. Категория — чипы под header (горизонтальный скролл).

```
┌─────────────────────────────┐
│ ГЕОПУЛЬС   [Томск ▾]        │
├─────────────────────────────┤
│ [Кафе] [Аптеки] [Бары] [→]  │
├─────────────────────────────┤
│                             │
│        КАРТА                │
│                             │
│                             │
└─────────────────────────────┘
```

- **Чипа «Всё» нет.** `/api/v1/cells` требует категорию, и «все категории» — это не сумма: у каждой
  категории своя шкала `density_breaks`. Режим «всё» требует отдельной агрегации и своей шкалы —
  это не MVP. В v0.1 чип стоял в макете по ошибке.
- Легенда сворачивается в **иконку в левом нижнем углу, над постоянной строкой** (не в правом: там
  на десктопе легенда, и тап по тому же углу предсказуемее). Тап — разворачивает; развёрнутая легенда
  занимает не больше 50% высоты и не перекрывает строку атрибуции.
- Дисклеймер — одна строка 11px (как в §4.7; в v0.1 был 10px — привели к одному значению).
- Панель POI — bottom sheet (см. 4.6).
- Тач-цели: минимум **44×44px**, отступ между элементами ≥ 8px.
- Кнопки в шапке — только иконки (§4.9).

## 7. Технические требования

| Что | Значение |
|---|---|
| CSS | **Чистый CSS + CSS-переменные** (Tailwind для MVP отклонён — ADR 0012) |
| Иконки | Lucide React, 16/18/20px |
| Шрифты | Inter + IBM Plex Mono через `next/font/google` (самохостинг на сборке, лицензия OFL; сборке нужен доступ к fonts.googleapis.com) |
| Токены | CSS-переменные в `frontend/app/globals.css` (§2) |
| Тёмная тема | Не поддерживается |
| Контраст текста | ≥ 4.5:1 (WCAG AA); значения в §2 уже проверены |
| Контраст элементов интерфейса | ≥ 3:1 против фона (`--border-strong`, обводка пустых ячеек) |
| Focus | Все интерактивные элементы — видимый outline 2px `--accent`, offset 2px (`:focus-visible`) |
| Анимации | UI ≤ 300ms; при `prefers-reduced-motion: reduce` — отключены |
| Скринридеры | Карта (canvas) недоступна: `aria-busy` на время загрузки, статусы — `aria-live`, доступный эквивалент данных — список объектов в панели и экспорт CSV |

**Проверка:** Playwright снимает главную страницу в 1280×800 и 390×844 — до появления эталонных
скриншотов это артефакт для ручной проверки, после 7a добавляем `toHaveScreenshot` с эталонами
(в v0.1 «сверка с ожидаемым» была неисполнима: эталонов нет).

## 8. Стилистические запреты

- Градиенты (кроме дискретной тепловой шкалы).
- Тени — только у всплывающих элементов (легенда, панель POI, модалки, меню) и focus-ring, одна
  `--shadow-raised` (§2.6).
- Скругления > 8px (включая нижнюю «шторку»).
- Тёмная тема.
- Кастомные скроллбары.
- Пульсации, мерцания, «привлекающие внимание» анимации.
- Более 2 акцентных цветов в одном экране (синий `--accent` + сигнальная шкала YlOrRd).
