# ГЕОПУЛЬС — записка по развитию продукта

## Проблема, которую решаем

Основатель знает свой город — карта для него читается мгновенно. Но **менеджер по региональному развитию из другого города** видит набор цветных пятен без контекста:

- «Томск — это где? Какой это район по меркам России?»
- «Красноармейская, 101 — это центр или спальный район?»
- «78% пустых ячеек — город мёртвый или данные неполные?»
- «Мне нужно отчитаться перед руководством. Что я им покажу?»

**Ключевое:** мы даём данные, а он ищет ответ. Для ответа нужен контекст, которого у него нет.

## Что видит менеджер сейчас

- Карту Томска с гексагонами
- Легенду «плотность POI/км²»
- Список кафе в ячейке

## Что ему на самом деле нужно

| Что он хочет | Что даём сейчас | Чего не хватает |
|---|---|---|
| Понять город в целом | Карта с точками | Районы города |
| Увидеть, где «горячо» | Тепловая карта плотности | Рейтинг районов |
| Сравнить зоны | Клик по одной ячейке | Сравнительная таблица 3–5 зон |
| Отчитаться руководству | Скриншот карты | Экспорт с подписями |
| Понять, стоит ли ехать | — | Профиль города |

## Три вещи, которые превращают карту в продукт

### 1. Районы города как единица анализа

Менеджер мыслит районами, а не гексагонами. Добавить слой административных границ (OSM или Росстат) и показывать сводку по каждому району:

```
ОКТЯБРЬСКИЙ РАЙОН
  Кофеен: 45
  Аптек: 32
  Плотность: высокая
  Точек притяжения: 8 (ТГУ, 2 ТЦ, 3 офисных центра)
  → Рекомендуем для открытия: да
```

Это даёт точку входа: он видит район, а не гексагон.

### 2. Профиль города

Одна страница, объясняющая город за 10 секунд:

```
ТОМСК
Население: 569 000
Площадь: 177 км²
Кофеен: 271
Аптек: 257
Салоны красоты: 342
ПВЗ: 501

Районы:
  Октябрьский — 45 кофеен
  Ленинский — 38 кофеен
  Кировский — 52 кофеен
  Советский — 29 кофеен
```

Это то, что менеджер покажет руководству как первый слайд.

### 3. Сравнение зон side-by-side

Менеджер не хочет смотреть по одной ячейке. Он хочет сравнить 3–5 вариантов:

```
┌──────────────┬──────────┬──────────┬──────────┐
│              │ Зона А   │ Зона Б   │ Зона В   │
├──────────────┼──────────┼──────────┼──────────┤
│ Кофеен       │ 3        │ 12       │ 1        │
│ Офисов       │ 8        │ 3        │ 2        │
│ Жилых домов  │ 12       │ 5        │ 18       │
│ Остановок    │ 2        │ 1        │ 1        │
│ Вердикт      │ Средне   │ Перегрев │ Мало     │
└──────────────┴──────────┴──────────┴──────────┘
```

Это то, что он вставит в презентацию.

## Что это меняет в продукте

Сейчас ГЕОПУЛЬС — **инструмент исследования** (открой, посмотри, кликни). Для менеджера по развитию нужен **инструмент отчёта** (выбери, сравни, экспортируй).

**Минимальные изменения:**

1. Добавить слой районов и сводку по ним
2. Сделать страницу «Профиль города» — сводка по категориям
3. Добавить режим сравнения — выбрать 3–5 зон и увидеть таблицу
4. Улучшить экспорт — не просто CSV, а PDF с подписями и легендой

## Какие метрики давать

**Честные (наблюдения, не прогноз):**

| Показатель | Как считается |
|---|---|
| Конкурентов в зоне | Число POI категории в ячейке |
| Рядом с чем | Ближайшие точки притяжения (офисы, вузы, парки, остановки) |
| Где живут люди | Плотность жилых зон (OSM) |
| Характер района | Преобладающий тип застройки |
| Сводка факторов | Взвешенная сумма, компоненты видны |

**Чего не можем дать:**

- Реальный пешеходный трафик (нет доступа к данным операторов/Яндекса)
- Прогноз выручки и окупаемости (нет данных о выживаемости точек)
- Демография на уровне квартала (Росстат даёт район, WorldPop — прокси)

## Приоритет внедрения

1. **Сводка по районам** — чтобы менеджер понял город
2. **Сравнение зон** — чтобы он выбрал лучшую
3. **Профиль города** — чтобы отчитаться руководству
4. **PDF-экспорт** — чтобы вставить в презентацию
